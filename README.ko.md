# 담백 · Dambaek

[English](README.md) | **한국어**

담백은 한국어 초안에서 번역투와 군더더기를 덜고 글쓴이의 뜻과 말투를 살리는 편집 지침이다. 문단을 다듬을 때는 앞뒤 내용으로 관계가 분명한 문장을 잇고, 설명에 필요한 조건은 남긴다.

## 문맥에 따라 판단하기

특정 표현은 점검할 단서이지 금칙어가 아니다. [조건부 패턴 예시](references/patterns.md)에서 덜어낼 때와 정보·관계상 남겨야 할 때를 함께 보여준다. 검토도 구조 검사, 의미 보존, 실제 표현 개선으로 나누어 진행한다. [검토 방법](tests/README.md)을 참고한다.

## 블로그 밖에서도

이메일, 일상 메시지, 소개글, 감상과 관계 표현에도 같은 지침을 쓸 수 있다. 상대와의 관계, 높임말, 감정, 부탁·약속의 강도를 살리고 어색한 부분만 다듬는다. 모든 글을 블로그 문체로 바꾸거나 제목·표·결론을 붙이지 않는다. [일반 글 편집 예시](references/everyday-writing.md)를 참고한다.

## 이런 부분을 다듬는다

| 표현 | 편집 방향 |
| --- | --- |
| 반복되는 긴 대시 | 문맥에 맞게 하이픈, 쉼표, 문장 나누기로 정리한다. |
| 설명 뒤에 덧붙이는 불필요한 “하지만 ~는 아니다” | 의미 없는 단서는 덜고, 독자의 이해에 필요한 구분은 남긴다. |
| 식상한 서론과 과장된 설명 | 실제 주제로 시작하고 구체적으로 쓴다. |
| 반복되는 연결어와 어미 | 억지로 변주하지 않고 자연스러운 흐름을 만든다. |
| 과도한 볼드와 장식적인 구성 | 독자에게 필요한 강조만 남긴다. |
| 번역투와 어색한 한국어 | 사실, 범위, 말투를 유지하면서 자연스럽게 고친다. |

## 간단한 예시

**다듬기 전**

> 이번 글에서는 새롭게 출시된 모델의 문서 작성 기능에 대해 자세히 알아보겠습니다. 하지만 모든 문제를 해결하는 만능 도구는 아닙니다.

**다듬은 뒤**

> 새 모델의 문서 작성 기능을 살펴보겠습니다.

상투적인 도입과 의미 없는 단서를 줄이고 높임말 어미는 유지한 예시다. “PDF 내보내기를 지원하지 않는다”처럼 구체적인 제약은 유지한다. 문체는 글쓴이가 지정한 기준을 우선한다.

## 원하는 AI에서 사용하기

1. [SKILL.md](SKILL.md)를 열고 내용을 복사한다.
2. 아래 요청문을 이용해 원하는 AI에 지침과 원문을 함께 붙여넣는다.
3. 수정본에서 사실, 조건, 인용이 유지됐는지 검토한다.

핵심은 읽을 수 있는 지침 파일이다. 담백 자체는 별도 앱 설치나 API 키를 요구하지 않으며, 실제 편집은 선택한 AI 서비스가 수행한다. AI가 링크를 읽지 못하면 지침 내용을 직접 전달한다.

```text
아래 글을 담백 지침에 따라 자연스러운 한국어로 다듬어줘.
원래 의미, 사실, 수치, 인용과 글쓴이의 관점을 유지해줘.
불필요한 표현만 덜어내고, 수정본과 주요 변경 이유를 보여줘.

[담백 지침]
여기에 SKILL.md 내용을 붙여넣기

[원문]
여기에 다듬을 글을 붙여넣기
```

| 도구 | 지침 전달 방법 |
| --- | --- |
| ChatGPT | 원문과 함께 붙여넣거나, 프로젝트 참고 자료로 저장하고 프로젝트 지침에서 사용을 지정한다. |
| Claude | 원문과 함께 붙여넣는다. 사용자 스킬로 설치하려면 `SKILL.md`와 `references/`를 담은 `dambaek` 폴더를 ZIP으로 묶어 Claude에 업로드한다. |
| Notion AI | 편집 요청에 지침을 붙여넣거나, 지침을 페이지에 보관하고 원문과 함께 명시적으로 참조한다. |
| 그 밖의 AI | 같은 대화 맥락에 텍스트 지침과 원문을 함께 제공한다. |

공식 안내와 검증 상태는 [도구별 사용 안내](docs/platforms.md)에서 확인할 수 있다.

## 편집 원칙

- 사실, 불확실성, 수치, 이름, 인용, 글쓴이의 입장을 보존한다.
- 관찰 횟수와 개체 수를 구분한다. “오전과 오후에 수달을 봤다”는 두 번 봤다는 뜻이다. 같은 수달이었을 수도 있다.
- ‘만’이 무엇을 한정하는지 살핀다. “민지가 사진만 보냈다”는 보낸 자료를, “민지만 사진을 보냈다”는 보낸 사람을 한정한다.
- 자료로 확인한 범위를 남긴다. “공지에는 날짜가 없다”만으로 행사 날짜가 미정이라고 쓸 수는 없다.
- 필요한 주의사항과 의미 있는 대조는 남긴다. 삭제 전에 문장의 역할을 살핀다.
- 한국어 높임말과 요청한 문서 형식을 유지한다.
- 코드, 링크, 표, 인용문이 무심코 바뀌지 않도록 보호한다.
- 글쓴이가 검토할 수 있도록 중요한 변경을 보여준다.
- 모든 글을 같은 말투로 만들기보다 글쓴이의 취향을 따른다.

## 완성된 글에서 배우기

금지 표현 목록뿐 아니라 실제 블로그 최종본도 참고한다. [블로그 편집 참고](references/blog-editing.md)에 구체적인 도입, 문단 연결, 표의 해설, 발표 자료와 직접 경험의 구분을 관찰과 편집 기준으로 나누어 정리했다. 원문을 데이터 묶음으로 복제하지 않고 출처 링크를 남겼다.

한다체, 표 활용, 1인칭 최소화는 선택 가능한 기술 블로그 방식이다. 개인 후기나 정중한 이메일에 일률적으로 적용하지 않는다.

## 예시와 검토

[편집 예시](references/examples.md)와 [동작 검토 사례](tests/README.md)에서 유용한 수정과 반드시 보존해야 하는 정보를 확인할 수 있다.

현재 초기 개발 단계다. 도구별 사용 안내는 공식 문서를 바탕으로 작성했으며, 각 제품에서 담백을 실제 실행하는 검증은 남아 있다. 검토 사례는 기대 동작을 설명하며 측정된 개선 효과를 뜻하지 않는다.

## 기여하기

한국어 수정 전후 예시, 원래 의미가 달라진 수정, 더 나은 사용 안내를 제안할 수 있다. 작고 구체적인 사례가 특히 도움이 된다.

제안 양식과 검토 기준은 [CONTRIBUTING.md](CONTRIBUTING.md)에 정리했다. 직접 작성했거나 공유할 수 있는 글을 사용하고, 공개하기 전에 개인정보를 제거한다.
